# Deploying X GYM — step by step

This folder is ready to deploy. **Read the 3 things below first**, then follow *Option A (Render)*.

## ⚠️ 3 things to know first

1. **Secrets.** `.env` (included, git-ignored) holds your admin password and secrets. Open it, see your
   `ADMIN_PASSWORD`, and change it to something you'll remember. **Never upload `.env` to GitHub** —
   you'll copy the values into your host's dashboard instead.
2. **Your data lives in one file (`xgym.db`).** Free hosts erase local files when the app restarts or
   redeploys. So either use a **persistent disk** (paid on most hosts) **or** download a backup from
   **Admin → Settings → Download full backup** regularly — and use **Restore** to put it back.
3. **`xgym.db` is not in this zip on purpose** — so unzipping over your folder can't overwrite your real
   members. A fresh database is created automatically on first start.

---

## Before deploying: test it on your computer (2 minutes)

```bash
pip install -r requirements.txt
python3 app.py
```
Open `http://127.0.0.1:5000/admin`, log in with the password from `.env`, add a test member, renew
them, look at Revenue. Delete the test member afterwards (the `xgym.db` file that appears is yours —
it is git-ignored). Optional: `python3 -m unittest discover -s tests` runs 62 automated tests.

## Option A — Render (works with this folder as-is)

**1. Put the code on GitHub**
- Create a **private** repository and upload everything in this folder **except `.env`**
  (`.gitignore` already excludes it, along with `*.db`).

**2. Create the service**
- Render dashboard → **New + → Blueprint** → pick your repo. It reads `render.yaml` automatically.
  (Or *New + → Web Service* manually: Build `pip install -r requirements.txt`,
  Start `gunicorn app:app --workers 1 --threads 4 --timeout 60`, Health check path `/api/health`.)

**3. Set the secrets** (Dashboard → your service → **Environment**)

| Key | Value |
|---|---|
| `ADMIN_PASSWORD` | the password from your `.env` (or your new one) |
| `SECRET_KEY` | auto-generated by the Blueprint (or copy from `.env`) |
| `CRON_SECRET` | auto-generated by the Blueprint (or copy from `.env`) |
| `SESSION_COOKIE_SECURE` | `1` (already set by the Blueprint) |
| `REVENUE_PIN` | *optional* — a PIN only you know, to lock the Revenue page |
| `META_ACCESS_TOKEN`, `META_PHONE_NUMBER_ID` | *optional* — WhatsApp automatic sending (see below) |

**4. Open it**
- Public site: `https://<your-service>.onrender.com/`
- Admin: `https://<your-service>.onrender.com/admin`  (never linked from the public site)

**5. Make your data safe — pick one**
- **Free plan:** there is no persistent disk, and the service sleeps after ~15 minutes without visitors
  (first request afterwards takes a while to wake it). The database resets whenever the service restarts or
  redeploys. Download a backup from **Settings** at the end of each week (and before every redeploy);
  to recover, **Settings → Restore from a backup**.
- **Paid plan:** in `render.yaml`, uncomment the `disk:` block **and** the `DB_PATH` line, commit, and
  the database then survives redeploys. *(Pricing/plans change — check Render's current plans.)*

## Option B — any other host that runs Python (Railway, Fly.io, a VPS, PythonAnywhere…)

- Start command (also in `Procfile`): `gunicorn app:app --workers 1 --threads 4 --timeout 60`
- Install: `pip install -r requirements.txt`  ·  Python 3.10+ (tested on 3.12)
- Set the same environment variables as above. Keep it at **one worker** (SQLite is a single file).
- Put the database on a persistent volume and set `DB_PATH` to it (for example `/data/xgym.db`).

## After it's live — checklist

- [ ] Log in at `/admin` and **change the default-looking password** if you haven't.
- [ ] Add one real member, renew them, record a sale, open **Revenue** — confirm the numbers.
- [ ] **Settings → Plan prices**: check they match your price list.
- [ ] **Settings → Download full backup** once, and save the file somewhere safe (Google Drive).
- [ ] Open the admin on your **phone** and add it to your home screen.
- [ ] *(Optional)* set `REVENUE_PIN` if staff will use the admin.
- [ ] *(Optional)* WhatsApp automatic sending — see below.

### Daily automatic reminders + WhatsApp (optional)
1. Get `META_ACCESS_TOKEN`, `META_PHONE_NUMBER_ID` from Meta for Developers → your app → WhatsApp → API Setup,
   and an **approved** message template (`META_TEMPLATE_NAME`).
2. Add them in the host's Environment settings. In **Admin → Messages** the "automatic sending isn't set up"
   warning disappears.
3. For the once-a-day auto reminder, use a free scheduler (e.g. cron-job.org) to call
   `POST https://<your-site>/api/reminders/check-tomorrow` daily with the header
   `X-CRON-SECRET: <your CRON_SECRET>`.
Without these, everything else works; the green WhatsApp buttons still open WhatsApp with the message ready.

## Updating the site later
Push the new code to GitHub → the host redeploys. On the free plan, **download a backup first**, and
restore it after if the data was reset. The app upgrades an older database by itself on start.

## Troubleshooting

| Problem | Fix |
|---|---|
| Can't log in | `ADMIN_PASSWORD` in the host's Environment must match what you type. Too many wrong tries → wait 15 minutes |
| "Session expired" keeps appearing | `SESSION_COOKIE_SECURE=1` only works on **https** — use the `https://` address |
| Members vanished after a deploy/restart | Free plan has no disk → **Settings → Restore from a backup**. For a permanent fix use a persistent disk + `DB_PATH` |
| First page load is slow | Free plans sleep when idle; the first visit wakes them |
| WhatsApp send fails | Check the Meta values and that the template name is approved; **Messages → History** shows the exact reason |
| Revenue asks for a PIN | `REVENUE_PIN` is set — that's the PIN. Remove the variable to turn it off |
| Check what's in the database | Log in, then open `/api/debug/status` |
